Памятка по работе с GitHub.com специально для твоего проекта:

Вот логика работы твоей связки без лишней теории:

1. GitHub — это склад и конвейер

  • Хранилище: Все твои файлы (тексты, стили, настройки) лежат в репозитории weblog. Это единственное место правды.
  • Сборщик (Jekyll): Когда ты делаешь коммит, GitHub автоматически запускает Jekyll. Он берет Markdown-файлы из _posts, подставляет их в шаблон _layouts/default.html, применяет стили из style.css и генерирует готовые HTML-страницы.
  • Публикация: Готовые HTML-файлы выкладываются на сервер по адресу avecher.github.io/weblog/. Ты никогда не загружаешь HTML вручную — только исходники.

2. VS Code (github.dev) — это пульт управления

  • Редактор, а не хостинг: Он не собирает сайт и не публикует его. Он только меняет файлы на складе (GitHub).
  • Структура: Показывает реальное дерево папок (_posts, _layouts). Ты видишь, где создаешь файл, и не можешь ошибиться с путем.
  • Предпросмотр: Позволяет увидеть форматирование Markdown до коммита. Но это только превью текста, а не работающий сайт.
  • Git-клиент: Управляет версиями. Кнопка «Commit & Push» отправляет изменения на склад и триггерит сборку.

3. Связь между ними

  1. Ты пишешь текст в VS Code → нажимаешь Commit & Push.
  2. Файл улетает на GitHub.
  3. GitHub видит изменение → запускает Jekyll → пересобирает весь сайт.
  4. Через 2–3 минуты новая версия появляется по ссылке.

Ключевое правило: VS Code создает исходный код. GitHub превращает его в сайт. Между ними нет прямой связи «нажал кнопку — увидел результат». Всегда есть этап сборки на стороне GitHub.

1. Как создать новую запись (всегда делай так)

  1. Зайди в репозиторий weblog.
  2. Кликни на папку _posts (с нижним подчёркиванием). Убедись, что ты внутри неё (вверху написано weblog / _posts).
  3. Нажми кнопку Add file → Create new file.
  4. В поле имени пиши ТОЛЬКО дату и название: 2026-11-15-novaya-zapis.md.
    • ⛔ НЕ пиши _posts/ в начале. Ты уже внутри папки.
    • ✅ Пиши просто имя файла.
  5. Вставь текст записи.
  6. Нажми Commit changes.

2. Что такое нижнее подчёркивание _

  • Папки _posts, _layouts — это служебные папки Jekyll. Они не становятся страницами сайта. Это «кухня».
  • Файлы без подчёркивания (index.html, style.css) — это страницы сайта. Это «витрина».
  • Никогда не называй свои посты или страницы с подчёркиванием в начале, если не знаешь точно зачем.

3. Если случайно создал файл не там

Не пытайся переименовать через редактор — поле заблокировано.

  1. Скопируй текст файла.
  2. Отмени редактирование (Cancel).
  3. Перейди в правильную папку.
  4. Создай новый файл с тем же именем (без префикса пути).
  5. Вставь текст. Закоммить.
  6. Удали старый файл из неправильной папки.

4. Медиа (аудио/видео)

  • Не загружай файлы больше 100 МБ прямо в папку _posts.
  • Для аудио/видео используй GitHub Releases (раздел Releases справа в репозитории) или ссылки на ВК.
  • Вставляй плееры через HTML-теги <audio> и <video> прямо в текст записи.

5. Проверка перед коммитом

Перед тем как нажать «Commit changes», всегда смотри на хлебные крошки вверху:

  • Должно быть: weblog / _posts / [имя-файла].md
  • Если видишь: weblog / _posts / _posts / ... — ты ошибся, отменяй и начинай заново.

Эта памятка — твой чеклист. Сохрани её себе. Каждый раз, когда садишься писать новую запись, открывай её и следуй пунктам. Через 3–4 записи руки запомнят, и инструкция станет не нужна.

Вот полная последовательная инструкция для развёртывания проекта «Хроника проекта» с нуля. Все файлы даны целиком, без дополнений и правок по ходу.

Шаг 1. Создание репозитория

  1. Зайди на github.com → New repository.
  2. Имя: weblog.
  3. Поставь галочку Public.
  4. Нажми Create repository.

Шаг 4. Папка _layouts и файл default.html

  1. Создай папку _layouts (Add file → Create new file → _layouts/.gitkeep → Commit).
  2. Удали .gitkeep.
  3. Создай файл _layouts/default.html:
<!DOCTYPE html>
<html>
<head>
    <meta charset="utf-8">
    <title>{{ page.title }}</title>
    <link rel="stylesheet" href="{{ site.baseurl }}/style.css">

<body>
    <header style="margin-bottom: 40px; padding-bottom: 20px; border-bottom: 1px solid #d0d7de;">
        <a href="{{ site.baseurl }}/" style="font-family: ui-monospace, SFMono-Regular, monospace; color: #24292e; text-decoration: none; font-size: 1.1em; font-weight: bold;">

        </a>

        <h1 style="font-size: 1.8em; margin-bottom: 24px; font-weight: normal; color: #24292e;">{{ page.title }}</h1>

Шаг 6. Файл index.html (создать в корне)

---
layout: default
---

<h1><a href="{{ site.baseurl }}/">Хроника проекта</a></h1>

{% for post in site.posts %}
<article>
  <time>{{ post.date | date: "%Y-%m-%d" }}</time>
  <h2><a href="{{ site.baseurl }}{{ post.url }}">{{ post.title }}</a></h2>
  {{ post.excerpt }}
</article>
{% endfor %}

Шаг 7. Включение GitHub Pages

  1. Settings → Pages.
  2. Source: Deploy from a branch.
  3. Branch: main, Folder: /(root).
  4. Save.
  5. Подожди 3–5 минут до появления зелёной ссылки.

Шаг 8. Проверка

Открой https://avecher.github.io/weblog/. Главная страница должна отображаться со списком постов. Клик по заголовку поста должен открывать страницу с заголовком, текстом, навигацией «← Хроника проекта» и футером.

Памятка для создания следующих записей:

  • Всегда создавай файлы внутри папки _posts (кликни на неё → Add file → Create new file).
  • Имя файла: ГГГГ-ММ-ДД-название.md (без префикса _posts/).
  • Обязательный фронтматер в начале каждого файла:
    ---
layout: default
title: Заголовок записи
date: ГГГГ-ММ-ДД
---
  • Для медиа используй прямые ссылки или GitHub Releases. Теги <audio> и <video> вставляются в текст как HTML.
